# daily-sports: project memory

## Purpose
Daily research-only sports page: every competitive sport with events in the next 24h
(Europe/Dublin, all times Irish). **No bookmaker odds** in this version; the value is
fixtures + free model predictions + context. Published as one self-contained HTML artifact.

## Decisions (do not re-litigate)
- Schedule: durable Routine, `CRON_TZ=Europe/Dublin 0 9 * * *`, fresh session per run.
  Routine id: trig_01GRo9osU7e8rptbiVArweg8 (created 2026-10-01). It wakes a dedicated home session
  (session_015XnLaoJGSmGFkRex5FnoEi) that has this repo attached, because the Routine API cannot attach a repo
  and fresh-session Routines start empty. The first Routine (trig_01BsFs...) failed for that reason and was deleted.
  The home session needs `pip install pytest tzdata` after a container restart. Persistent-session Routines
  cannot send a push notification via the API; check the session in the app (or recreate in the claude.ai Routines UI to get push).
- Notification: in-app/push only. NO email. Gmail connector is not used (user wants it disconnected).
- Same artifact URL updated daily: https://claude.ai/artifact/EHjGCjyvys3pUB95UzdF68 (first published 2026-10-01; republish `out/artifact.html` with that `url`).
- Page shows ONLY fixtures that have at least one model prediction (user decision 2026-11-06). `src.build.build(..., models_only=True)` drops the rest (`window.filter_modelled`); the page header says how many are hidden. `fixtures.json` snapshots still keep everything.
- Page controls (user request 2026-11-07): football rows show a DERIVED score (independent-Poisson fit to Predicd win/draw/loss %, `src/score.py`; Predicd publishes no score) and hide when predicted margin < 2 goals; NHL rows use Odds Shark's published score and hide when margin < 0.75; NFL rows (Odds Shark published score) hide when margin < 6.5 points (user request 2026-11-08). The thresholds are editable inputs on the page (set 0 to see all); filtering happens in the browser, so all modelled rows remain in the HTML. Tennis rows (SetProb win %, no score) show the favourite's win % and hide when the win-probability gap (favourite % minus other player's %, percentage points) is < 50 (user request 2026-11-11, default 50, editable `min-tennis`, with a range slider `min-tennis-slider` kept in sync; page stamp is now 'Layout v4'). Other sports (NBA, MLB, ...) are not margin-filtered. Always label derived scores as derived. Layout v3 (user feedback 2026-11-07, twice: they could not see the controls or scores): the margin filter sits directly above each football/NHL table (plain `<div>`, not a `<form>`), the page top has Sort + status + a 'Layout v3' stamp, the predicted score is a highlighted box (solid = published, dashed = derived), `validate.check_page` warns if any of it is missing, the predicted score has its own prominent column, rows default to largest margin first (a Sort select switches to kick-off time), and the default thresholds are ALSO applied in the HTML itself (class `off`) so the page is right even if the host never runs its script.
- Python 3.11 + pytest, TDD (red -> green per module). Run: `python3 -m pytest -q`.
- Data collection is done by Claude (feeds, web search, subagents); everything downstream of
  `fixtures.json` is deterministic code in `src/`, unit-tested without network.

## Rules
- Window = now .. now+24h computed with zoneinfo `Europe/Dublin` (never fixed offsets). Drop finished matches; keep started-not-finished as LIVE.
- Every datum carries provenance {source,url,fetched_at,kind}; kind in
  official-feed | statistical-model | ai-model | human-pick. Be honest: predicd = statistical,
  Covers/Odds Shark = computer simulation, not a neural net; never present paywalled/stale data as current.
- Stale source (fixtures don't match feed) -> discard, list under "Sources skipped".
- Flags: model-vs-model spread >= 10pp; model-vs-consensus >= 5pp when 2+ models. Single model = "low confidence".
- Page must have: dark mode, responsive, timestamp + sources footer, "prices move / gamble responsibly" note.

## Layout
prompts/daily-research.md (the Routine prompt) | src/ (window, schema, normalise, dedupe, elo, render, validate) | tests/ | fixtures/ | out/ (gitignored)

## Data sources that worked (2026-10-01, after allowlisting *.domain wildcards)
- Football: www.live-footballontv.com (HTML `.fixture` blocks, UK/IE local time) + www.predicd.com/en/football (win/draw/loss %, times are Irish time).
- US sports/rugby/tennis/MMA/golf: espn.com pages embed JSON in `window['__espnfitt__']` (schedule/scoreboard per date). Odds Shark picks (predicted scores, not probabilities) from www.covers.com/picks/<league>; 0.00 = not published.
- Blocked/403: atptour.com, espncricinfo.com, site.api.espn.com. Not collected: cricket, darts, snooker, boxing, GAA, racing, esports.
- Subagents may report 'plan mode' and stop after fetching; the main session then parses the saved pages. Parsing scripts are throwaway (scratchpad), the deterministic code is in src/.
- Collector: `python3 -m collect.run fixtures.json` (modules in collect/, pure parsers unit-tested; live runs found two bugs the unit tests missed, so keep running it live after changes). Predicd's time zone has flipped between Irish time and UTC between fetches: `collect.football.align` detects the shift from fixtures present in both sources. Predicd drops games once they start, so a late-day run loses models for in-progress games (the 09:00 run is unaffected).
- Tennis model (added 2026-11-11, user request): `collect/setprob.py`. SetProb (setprobability.pages.dev, kind statistical-model, labelled SetProb) is read from the site's own JSON endpoint `https://setprobability.pages.dev/api/fixtures?date=YYYY-MM-DD&tour=<atp|wta|atp-challenger|wta-challenger>` (the one its page loads; undocumented, so it may change; the run falls back to the ATP list in the server-rendered HTML if the feed fails). Only `predicted_winner` + `confidence` (win %) are read. The rows also carry betting-market odds (`odds_*`, Kalshi): NEVER collect or show them (tests assert this). Matched to ESPN tennis fixtures by surname (`same_player`: tolerates 'Burillo' vs 'Burillo Escorihuela'; first names differ, e.g. Aleksandr/Alexander) and within 12 h of kickoff. ESPN lists no ATP Challengers, so SetProb matches ESPN does not list (23 ATP Challengers today) are ADDED as SetProb-sourced fixtures (`setprob_only_fixtures`: needs a known kickoff inside the window, skipped if an ESPN fixture within 3 h shares a player, competition 'ATP Challenger - <tournament>', sources = SetProb page; user request 2026-11-11). Doubles and 'TBD' ESPN rows have no model. Tennis rows show win % bars only, with no predicted score, so no margin filter. Probed and rejected 2026-11-11: dimers.com (JavaScript shell, unreadable), cuetracker.net (snooker predictions stale since 2021). Hosts added to the Default environment's allowlist: www.dimers.com, setprobability.pages.dev, cuetracker.net, www.cuetracker.net.
- Page display rules (user request 2026-11-12): EVERY model on a fixture is shown in its Model predictions cell (probability bar, or the score for score-only models like Odds Shark), with a 'single source, low confidence' note when there is one model and a disagreement flag when 2+ models differ by 5+ pp; the tennis gap filter averages the gaps of all two-way models. SetProb's per-factor breakdown (`prob_factors`: Elo, H2H, last 10, surface...) is shown under its bar as the favourite's chance per factor; these are SetProb's own components, NOT separate models. Totals: the nav chips and each section heading show 'shown of total modelled' (e.g. 'Tennis 5 of 26'), so the filter never hides how many modelled fixtures exist.
- Cup games + Flashscore previews (user request 2026-11-12): football rows whose competition `src/cups.py::is_cup` calls a domestic cup go in a collapsed `<details class="cups">` table below the football table (favourites often rotate or throw cup ties; same margin filter, own 'N of M shown' count, an in-panel message when the filter hides all of them). Flashscore: `collect/flashscore.py`. Day feed `https://www.flashscore.com/x/feed/f_1_<day>_0_en_1` (day 0 today, 1 tomorrow; needs header `x-fsign: SW9D1eZo`, the constant its own page sends) lists every football match (¬~AA÷id¬AD÷unix¬AE÷home¬AF÷away, competition in ¬ZA÷). Match page `https://www.flashscore.com/match/<id>/` REDIRECTS (curl needs -L); previews live in `<div id="eventPreview">` with sections (Match News and Current Form, Head-to-Head, Hot Stats, Key Players, Betting Analysis) and an 'Author:' line; only some matches have one (about half of the modelled fixtures on a normal day). The 'Betting Analysis' paragraph names the writer's market: `parse_pick` reads market + selection + which outcomes it covers (result, double chance, handicap, win to nil, margin, HT/FT, home/away win + goals; over/under and BTTS name a market but cover no outcome). STAR = the pick covers Predicd's top outcome (`src/preview.py`); never show prices (tests assert it). Only previews for MODELLED football fixtures are fetched. The synopsis is written by Claude each day (prompt step 3b) into `previews/YYYY-MM-DD.json` and attached with `python3 -m collect.synopses`; the raw preview text stays in gitignored `out/previews_raw.json`. Page stamp is now 'Layout v5'.
- Flashscore preview formats (seen 2026-11-14): (1) writer previews (Nations League etc.) with sections Match News and Current Form / Head-to-Head History / Hot Stats / Key Players / Betting Analysis and an 'Author:' line: the pick is read from Betting Analysis; (2) English League One previews are AI-generated stats previews (sections Current Form - <team>, Head-to-Head Record, Key Players, Key Numbers, Match Notes, Betting Insights, no author) whose intro and Betting Insights quote BOOKMAKER-IMPLIED probabilities: they give no pick, no star, and none of those numbers may appear on the page or in synopses. `parse_pick` reads only 'Betting Analysis' (test locks this). Pick parser now also knows: half-time-only lead (market 'Half-time lead', covers nothing, never a STAR), 'win without conceding'/'win and keep a clean sheet' (Win to nil), 'a goal inside the opening N minutes' (Goal in first N minutes).
- Bold rule (user report 2026-11-13: Polona Hercog was bold but her opponent was the pick): the Match column used to bold the HOME side always, which read as the prediction. Now `src/score.py::favourite` decides: bold = the side the model(s) favour (Predicd top outcome, higher win %, higher score), nothing bold for a draw/tie, no model or disagreeing models. Tests in tests/test_favourite.py. The favourite is also outlined (`strong.fav`, user request 2026-11-13) so the selection stands out; never bold or outline anything for layout reasons alone.
- Women's fixtures (user request 2026-11-13, after a women's selection lost two accumulators): `src/gender.py::is_female` separates them from every section's main table into a collapsed `<details class="acc womens">` 'Women's fixtures' at the bottom (below the cup accordion; classes are now `acc cups` / `acc womens`, counts `acc-count`, empty message `acc-empty`). Counts still include them (shown of total); the star strip leaves them out and says how many. Page stamp is now 'Layout v6'.
- Country flags (user request 2026-11-20): football competition labels carry a flag via `src/country.py::competition_html` (name match on the label, since fixtures have no country field; England/Scotland/Wales use regional flag emoji, Northern Ireland the UK flag, UEFA = EU flag, AFC/CONCACAF/FIFA = globes; ambiguous labels such as Super League, Superliga, Liga 1 get no flag rather than a guess; the country is the hover tooltip). - All-sports view (user request 2026-11-22): a View select (`#view-mode`) switches to `#all-view`, one table of all sports ordered by kick-off, built in the browser by cloning the main-table rows that pass the filters (cup and women's accordion rows excluded, they stay in By sport view), each prefixed with a sport tag with an icon (`render.SPORT_ICON`, `data-icon`/`data-label` on each section; ordinary sport emoji, which render fine, unlike flag emoji). The per-sport margin filters stay visible in this view and the combined table rebuilds when they change. Page stamp 'Layout v8'.
