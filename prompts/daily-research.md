# Daily sports research (runs 09:00 Europe/Dublin)

Goal: a research page for every competitive sport with events in the next 24h. Free model predictions only, NO bookmaker odds. Times in Irish time.

1. **Setup.** `git pull origin claude/wonderful-cori-vxwyn9`; `pip install -q pytest tzdata`; `python3 -m pytest -q` must pass.
2. **Collect.** `python3 -m collect.run fixtures.json` fetches live-footballontv + Predicd (football), ESPN (NHL, NFL, NBA, WNBA, MLB, NCAA, tennis, rugby, MMA, golf), Covers/Odds Shark picks (predicted scores) and SetProb tennis win probabilities, merges them, aligns Predicd's time zone against the listings, and records every blocked or missing source under `skipped`. SetProb is read from its own JSON feed (`setprobability.pages.dev/api/fixtures`, tours atp, wta, atp-challenger, wta-challenger; falls back to the ATP list in its HTML) and matched to ESPN tennis fixtures by surname within 12 h; SetProb matches that ESPN does not list (e.g. ATP Challengers) are added as SetProb-sourced fixtures, never duplicated. The SetProb feed also carries betting-market odds: NEVER collect or show them. It never invents fixtures.
3. **Fill gaps (optional, only with data you actually fetched).** Cricket, darts, snooker, boxing, GAA, horse/greyhound racing, esports are not collected yet. If you can fetch a reliable source showing fixtures inside the window, append them to `fixtures.json` in the same schema (kickoff in ISO-8601 with offset, `models: []` unless a free source publishes a prediction) and remove that sport's "no collector yet" note. Otherwise leave the note. Do not use paywalled or stale data as current, and do not collect bookmaker odds.
4. **Build.** `python3 -m src.build fixtures.json out/index.html` (non-zero exit = quality gate failed; the page carries a WARNING banner, publish it anyway and say why). The build keeps ONLY fixtures that carry at least one model prediction; fixtures with no model are dropped from the page and the page says how many (`hidden` in the JSON result). Do not add them back by hand, and do not pass `models_only=False`. The page ('Layout v4') has:
   - a Sort select, a status line and the 'Layout v4' stamp at the top; the nav chips and every section heading show 'shown of total modelled' (e.g. 'Tennis 5 of 26'), updating live, so a filter never hides how many modelled fixtures exist;
   - a margin filter directly above each table: football default 2 goals, NHL 0.75 goals, NFL 6.5 points, and tennis a win-probability GAP (favourite % minus the other player's %, in percentage points) default 50, as a 0-100 slider linked to a number box. Football scores are DERIVED from Predicd's win probabilities (`src/score.py`, dashed box, labelled derived); NHL/NFL scores are Odds Shark's published scores (solid box); tennis rows show the favourite's win % in the box and no score. Other sports are not filtered;
   - EVERY model on a fixture in its Model predictions cell (probability bar, or the score for score-only models), 'single source, low confidence' when there is one, a disagreement flag when 2+ models differ by 5+ pp; for tennis, SetProb's per-factor breakdown (Elo, H2H, last 10, surface) under its bar, which are SetProb's own components, not separate models.
   All modelled rows stay in the HTML; the default thresholds are applied server-side (hidden rows carry class `off`), rows are sorted by margin descending, and the controls re-filter/re-sort in the browser. Fixtures stay in `fixtures.json` and `fixtures/YYYY-MM-DD.json` for the record, then create `out/artifact.html` with `artifact_fragment` from `src/render.py`.
4a. **Near-duplicate check** after collecting: pairs within 15 min of kickoff where one side has a model and the other not, listing those whose best team-name similarity (`collect.football._sim`) is above 0.55; each hit needs a glance (most are different games). A true duplicate pair means adding an alias in `collect.football.ALIASES` (with a test) before publishing.
4b. **Self-check.** `python3 -m src.build` already adds a WARNING if the score column, score boxes or margin controls (football, NHL, NFL, tennis) are missing (`validate.check_page`). After publishing, tell the user the layout stamp ('Layout v4') so a stale cached copy is easy to spot.
5. **Publish** `out/artifact.html` as an Artifact, updating the SAME single URL recorded in CLAUDE.md (read it first, then publish with `url`). There is only one artifact now; do not publish a second copy.
6. **Save.** Copy `fixtures.json` to `fixtures/YYYY-MM-DD.json`, commit and push to `claude/wonderful-cori-vxwyn9`. Put new learnings (blocked hosts, layout changes) in CLAUDE.md.
7. **Final message** (this is what the user reads): first line = artifact link. Then at most 4 lines: stale/missing/blocked sources, and the 2-3 most notable model disagreements (model vs model; there is no bookmaker comparison; say so when every model is single-source). Also give the counts: modelled fixtures in total (with the per-sport split, e.g. tennis 28, football 15), how many are shown at the default filters, and how many were hidden for having no model. Max ~5 lines.
